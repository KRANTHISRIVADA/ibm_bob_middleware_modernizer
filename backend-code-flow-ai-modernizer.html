2 · Job Status State Machine

Every job moves through these states stored in SQLite. The frontend polls GET /status to track progress.

CREATED → UPLOADED → RE_IN_PROGRESS → RE_COMPLETE → GEN_IN_PROGRESS → GEN_COMPLETE
Error paths: RE_IN_PROGRESS → RE_FAILED · GEN_IN_PROGRESS → GEN_FAILED

3 · Reverse Engineering Request Flow

What happens from the moment POST /api/jobs/:id/reverse-engineer is called:

1
HTTP Request enters Express
Helmet adds security headers. Morgan logs the request. Rate limiter checks 200 req/15min quota. auditLogger wraps res.json to intercept the response.
server.js → middleware stack
2
Router matches the route
router.post('/jobs/:jobId/reverse-engineer') matches. No multer on this route — it's just JSON. Calls triggerReverseEngineer.
routes/jobs.js : line 39
3
Controller validates state & fires async
Looks up the job in SQLite. Guards: job must exist and status must be UPLOADED or RE_FAILED. Sets status to RE_IN_PROGRESS. Calls jobOrchestrator.runReverseEngineer(jobId) — without awaiting it. Returns 202-style JSON immediately so the UI isn't blocked.
controllers/jobController.js : triggerReverseEngineer()
4
Orchestrator: find + parse the uploaded file
Reads uploads/<jobId>/ to find the file. Dispatches to the correct parser based on job.sourcePlatform.
jobs/jobOrchestrator.js : runReverseEngineer()
5
Parser extracts structured metadata
APIC: reads YAML with js-yaml → extracts endpoints, security schemes, x-ibm-configuration backend URLs, schemas.
DataPower: opens ZIP with adm-zip → parses XML configs with xml2js → extracts MPGW/WSP services, XSLT files, GatewayScripts, crypto.
IIB/ACE: opens ZIP → parses .msgflow XML, .esql text, .wsdl, .xsd, .properties files.
parsers/apicParser.js · datapowerParser.js · iibAceParser.js
6
Prompt builder wraps metadata into LLM instructions
Selects the correct prompt function (APIC/DataPower/IIB). Injects the parsed metadata JSON and the complexity level into a structured prompt. Returns a { system, user } object.
llm/prompts.js : buildAPICPrompt() / buildDataPowerPrompt() / buildIIBACEPrompt()
7
LLM Client calls OpenAI / watsonx
Reads LLM_PROVIDER env var. OpenAI path: POSTs to /v1/chat/completions with response_format: json_object — forces a pure JSON response. watsonx path: exchanges IBM API key for IAM bearer token first, then calls Granite model. Fallback: if no API key is configured (or call fails), builds stub data from the parsed metadata instead — the app never crashes.
llm/llmClient.js : invokeLLM() → invokeOpenAI() / invokeWatsonX()
8
Schema validator checks LLM output
Runs jsonschema validation against a required-field schema. Logs warnings if fields are missing but does not abort — partial data still produces useful artifacts.
llm/schemaValidator.js : validateRE()
9
Artifact Builder writes 14 Markdown + JSON files to disk
Creates artifacts/<jobId>/reverse/. Calls a dedicated builder function for each of the 14 document types — each renders the LLM JSON into readable Markdown tables and prose. Also writes full-reverse-engineering.json — the master file re-used by code generation.
artifacts/artifactBuilder.js : buildArtifacts()
10
DB updated → frontend poll detects completion
Sets job status to RE_COMPLETE in SQLite. The frontend is polling GET /status every 3 seconds — it detects the new status and navigates to the artifact viewer.
config/database.js : updateJob() → jobs table

4 · Code Generation Flow

Triggered by POST /api/jobs/:id/generate with body { "targetStack": "JAVA_SPRING_BOOT" }

1
Controller guards RE_COMPLETE status
Job must be RE_COMPLETE or GEN_FAILED. Stores targetStack on the job record. Fires runGenerate(jobId, targetStack) async.
controllers/jobController.js : triggerGenerate()
2
Orchestrator loads RE JSON as input
Reads artifacts/<jobId>/reverse/full-reverse-engineering.json — the complete reverse engineering specification produced in step 9 above. This is the LLM's "requirements document" for generation.
jobs/jobOrchestrator.js : runGenerate()
3
Generation prompt injects the full RE spec
Selects buildSpringBootPrompt, buildNodeJSPrompt, or buildPythonPrompt. Embeds the entire RE JSON and asks the LLM to return a { "files": [{ "path", "content" }] } array covering controllers, services, mappers, tests, Dockerfile, k8s YAML, etc.
llm/prompts.js : buildSpringBootPrompt() / buildNodeJSPrompt() / buildPythonPrompt()
4
LLM response validated → files written to disk safely
Schema validates genData.files array. Each file path is sanitised with a path-traversal strip (../ removed). Files are written to artifacts/<jobId>/generated/. Status set to GEN_COMPLETE.
jobs/jobOrchestrator.js : lines 86–100

6 · Module-by-Module Reference

🚪
server.js
backend/src/server.js
  • Entry point — bootstraps Express
  • Applies middleware in order: Helmet → CORS → JSON parser → Morgan logger → Rate limiter (200/15min) → Audit logger → Routes → 404 → Error handler
  • start() is async because db.init() loads the sql.js WASM before the server listens
  • require.main === module guard lets tests import app without starting the server
🗺
routes/jobs.js
backend/src/routes/jobs.js
  • Declares all 9 route handlers in one place
  • Configures Multer with disk storage — saves file as its original name under uploads/<jobId>/
  • File filter blocks anything not in: .yaml .yml .json .zip .wsdl .xsd .xml
  • Size limit read from MAX_UPLOAD_SIZE_MB env var (default 50 MB)
🎮
controllers/jobController.js
backend/src/controllers/jobController.js
  • One function per route — keeps routes thin
  • Fire-and-forget pattern: both triggerReverseEngineer and triggerGenerate call the orchestrator with .catch() instead of await — status updates happen via the DB, not the HTTP response
  • ZIP downloads use archiver piped directly to res — no temp ZIP file created on disk
  • All functions wrapped in try/catch → next(err) so errors flow to the error handler middleware
🔧
jobs/jobOrchestrator.js
backend/src/jobs/jobOrchestrator.js
  • The main processing brain — coordinates parse → LLM → validate → write
  • runReverseEngineer(): parse → build prompt → call LLM (or fallback) → validate → buildArtifacts → update DB
  • runGenerate(): load RE JSON → build prompt → call LLM (or fallback) → validate → write each file safely → update DB
  • Fallback builders (buildFallbackRE, buildFallbackGen) ensure the app never errors out without an API key — they extract whatever the parser found and fill the rest with placeholder text
🔍
parsers/apicParser.js
backend/src/parsers/
  • APIC: uses js-yaml to load YAML/JSON. Walks paths object to extract every endpoint. Reads x-ibm-configuration.assembly.execute to find backend invoke URLs
  • DataPower: uses adm-zip to iterate ZIP entries. XML files parsed with xml2js. Extracts MPGW/WSP service names, backend URLs, crypto identity credentials, stylesheet variables
  • IIB/ACE: opens ZIP, parses .msgflow XML to extract node graph, parses .esql with regex to find MODULE definitions, walks .properties files for endpoint URLs
🤖
llm/llmClient.js
backend/src/llm/llmClient.js
  • Single entry: invokeLLM(systemPrompt, userPrompt) — dispatches based on LLM_PROVIDER env var
  • OpenAI: uses response_format: { type: "json_object" } — guarantees valid JSON back, no regex parsing needed. Temperature 0.1 for deterministic output.
  • watsonx: first POSTs to IBM IAM to exchange API key for a bearer token, then calls Granite model. Extracts JSON from response text with a regex since watsonx doesn't have a JSON mode
  • Both paths time out at 120 seconds
📝
llm/prompts.js
backend/src/llm/prompts.js
  • 6 prompt builder functions: 3 for reverse engineering (one per platform) + 3 for code generation (one per target stack)
  • Each RE prompt embeds the full parsed metadata JSON and an exact JSON schema the LLM must fill — field names, types, and allowed enum values are all specified
  • Each Gen prompt embeds the full RE specification JSON and lists exactly which files to generate with their directory structure
📄
artifacts/artifactBuilder.js
backend/src/artifacts/artifactBuilder.js
  • Takes the LLM JSON output and renders 14 Markdown files + 1 full JSON file to artifacts/<jobId>/reverse/
  • Each of the 14 build functions reads specific fields from the LLM output and formats them as Markdown tables or prose
  • Returns the list of filenames written — logged by the orchestrator
🗄
config/database.js
backend/src/config/database.js
  • Uses sql.js — pure JavaScript SQLite (no native binary, no Visual Studio needed)
  • init() is async because sql.js loads a WASM file. If the DB file exists it loads it from disk; otherwise creates fresh
  • After every write (saveJob, updateJob, saveAuditLog), calls persist() which exports the in-memory DB back to disk as a binary file
  • Two tables: jobs (job state) and audit_logs (event trail)
🛡
middleware/auditLogger.js
backend/src/middleware/auditLogger.js
  • Wraps res.json to intercept every JSON response after it's written
  • Maps route patterns to event names (JOB_CREATED, FILE_UPLOADED, RE_TRIGGERED, etc.)
  • Only records events for successful responses (status < 400)
  • Saves jobId, event name, request path, and client IP to audit_logs table
